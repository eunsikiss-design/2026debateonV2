# 학생 보고서와 세특 시트 연동

교사 관리자 → 학생별 검토 → 기록 검토 · 세특에서 학생을 선택합니다.

1. 학생의 글·발언 원문을 선택하고 분석 버튼을 누릅니다.
2. 시간적·공간적·사회적·윤리적 관점의 근거와 토론 피드백을 확인합니다. 확인되지 않은 관점에는 추가 탐구 질문이 표시됩니다.
3. 세특 초안을 수정하고 저장합니다. 실제 학생은 원문 대조 후 검토 완료를 체크합니다.
4. **엑셀 다운로드 / PDF 다운로드**로 저장한 버전의 보고서를 받습니다. 수정 중에는 먼저 저장해야 합니다. 파일에는 활동 개요, 세특, 관점별 분석, 다음 활동 제안, 선택한 원문 전체가 들어갑니다. 이전 분석에 관점별 결과가 없다면 재분석합니다.

## Google Sheets 연결

- 서버의 Google Cloud 프로젝트에서 **Google Sheets API**를 활성화합니다.
- 전용 계정은 `GOOGLE_SERVICE_ACCOUNT_EMAIL`과 `GOOGLE_PRIVATE_KEY`로 설정합니다. 둘 다 없으면 기존 Firebase 서비스 계정을 사용합니다. 키는 서버 환경변수로만 관리합니다.
- 교사 화면의 ‘Google Sheets 연결 설정’에 표시되는 서비스 계정을 대상 스프레드시트의 **편집자**로 공유합니다.
- URL을 입력하고 ‘시트 연결’을 누릅니다. 학교별 연결 대상이 데이터 저장소에 유지됩니다. 연결 변경은 같은 학교의 교사에게 적용됩니다.
- `DebateOn_세특`에 교사 검토 완료한 세특을 저장할 때 자동 반영합니다. 과거 세특은 해당 학생을 선택하여 ‘저장한 세특 지금 연동’으로 보낼 수 있습니다.
- `DebateOn_연동시험`은 가상 학생 전용입니다. 가상 학생은 수동 연동만 가능하며 정식 세특 탭에 들어가지 않습니다.
- 고유 연동 키로 학생별 행을 찾아 갱신합니다. 같은 버전을 다시 보내도 행이 늘어나지 않습니다. 키·열 이름을 바꾸거나 중복시키지 마세요.
- 연동 방향은 **앱 → Google Sheets**입니다. 앱에서 수정·저장한 내용이 시트를 갱신합니다. 시트 수정 내용은 앱으로 돌아오지 않습니다.
- 실패해도 세특 저장은 유지됩니다. 오류를 해결한 뒤 다시 연동합니다. 연결 해제는 자동 연동만 중단하며 기존 시트 내용을 지우지 않습니다.
- 학생 원문 전체는 시트로 보내지 않습니다. 시트에는 학생 식별 정보, 저장한 세특, 검토 상태, 저장 버전과 시각을 기록합니다.

## 운영과 검증

현재 JSON 저장소는 한 서버 프로세스를 전제로 합니다. 운영 서버의 `DATA_STORE_PATH`를 영속 볼륨에 두어 초안·연결 설정·연동 상태를 보존하세요. 여러 인스턴스로 확장할 때는 저장소와 시트 쓰기 잠금을 공용 데이터베이스로 옮겨야 합니다.

`npm run test:reports`로 인용 검증, 권한, 파일 다운로드, 중복 방지, 오류 재시도를 확인합니다. `scripts/verify-student-reports.cjs`는 3114 가상 학급 미리보기 전용이며 실제 학생 데이터를 사용하지 않습니다.
